# Smart Campus Ordering

Smart Campus Ordering is a role-based Next.js (App Router) application for campus canteens and vendors. It uses Firebase for authentication and Firestore for data storage, and Cloudinary for image uploads.

## Quick start

1. Install dependencies:

```bash
npm install
```

2. Create a `.env.local` file at the project root and add the environment variables listed below.

3. Run the development server:

```bash
npm run dev
```

Open http://localhost:3000.

## Environment variables

Required client/env variables (place in `.env.local`):

- `NEXT_PUBLIC_FIREBASE_API_KEY`
- `NEXT_PUBLIC_FIREBASE_AUTH_DOMAIN`
- `NEXT_PUBLIC_FIREBASE_PROJECT_ID`
- `NEXT_PUBLIC_FIREBASE_STORAGE_BUCKET`
- `NEXT_PUBLIC_FIREBASE_MESSAGING_SENDER_ID`
- `NEXT_PUBLIC_FIREBASE_APP_ID`
- `NEXT_PUBLIC_CLOUDINARY_UPLOAD_PRESET`
- `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME`

Notes:
- Vendor onboarding uses the Firebase Identity Toolkit REST API; the frontend code expects `NEXT_PUBLIC_FIREBASE_API_KEY` to be present.
- Keep these values secret in production and use a proper secrets provider.

## Architecture & important locations

- App router pages and role-scoped layouts: `app/` (student, admin, vendor). The root layout is `app/layout.tsx` and the default redirect is `app/page.tsx`.
- Firebase init: `lib/firebase/firebase.ts` and `lib/firebase/firestore.ts` (exports `db`).
- Firestore service helpers: `services/firestore/*` (orders, menu, vendors, feedback, governance).
- Auth helpers: `services/auth/*` and `lib/firebase/auth.ts`.
- Cloudinary upload helper: `services/cloudinary/upload-service.ts`.
- Client-side cart store: `services/cart/cart-store.ts`.
- Type definitions: `types/` and enums in `constants/enums.ts`.

## Data model & behavior notes

- Order statuses: `pending`, `accepted`, `completed`, `delivered`, `rejected` (see `constants/enums.ts`).
- Vendors have a `createdAt` field used for a 3-day setup window (see `services/firestore/menu-governance-service.ts`). Documents without `createdAt` are treated as outside the window.
- Rate limiting for students is implemented via Firestore (`services/security/rate-limit-service.ts`).

## Development tips

- Use a local `.env.local` for dev variables and a secure secrets store for production.
- When inspecting timestamps from Firestore, note that Firestore Timestamps may need conversion to JS `Date` where required by types.
